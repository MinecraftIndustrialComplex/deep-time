# Ledger CRE: Core engine constants: plate geometry, noise, plate state, deformation lattice

Rows: 35. By status: `cited-unverified` 8, `uncited` 27

Added in stage 2, package WP-0 (2026-10-02), by reading the code as it stood on master 1aa0579 (stage 1 had not
covered it). Nothing here has been checked against its source. Paths are relative to the repository root; line
numbers are left out on purpose.

In scope: `crates/deeptime-core/src/plates/geometry.rs`, `plates/noise.rs`, `plates/state.rs` and `structure/deform/lattice.rs`, read in full. These four files hold very few numbers that stand for the Earth: they are data structures, a triangulation and graph walk, a value-noise function and a bake-time comparison harness. The rows are therefore mostly rules and conventions the files hard-wire (what a plate is, what a crust sample is, how noise features are sized, how the Noddy comparison is defined), plus the few numbers that carry a meaning (noise gain and lacunarity, comparison tolerances, the unit conventions of the state fields). Skipped as pure engineering: the integer hash constants and bit shifts in `noise::hash`, the sample-flag bit values (`HIDDEN` 1 to `SUBDUCTION_ZONE` 64), the numeric codes of crust type, orogeny type and regime (recorded once as vocabulary rows, not per code), array lengths (`pool::COUNT`, `regime::NAMES`), tie-break orders of the Dijkstra heap, the `NONE` sentinel, `u32::MAX` and infinity sentinels, `orogeny_myr = -inf`, the 8-pass cap of `connect_plates` (engineering bound, recorded inside CRE-008), the `.max(1)` and `.max(0.0)` guards, the `1e-6` plane-distance guard (recorded inside CRE-034 because it classifies agreement), the `step_by` and timing fields of `ColumnStats` and `NoddyCheck`, and everything in the `tests` modules. Not `pending-rewrite`: neither the headers of these four files nor the plate-force-balance design (`docs/design/plate-force-balance.md`, section 6 "What it replaces") says any of them is to be replaced. That section names `mod.rs`, `kinematics.rs`, `subduction.rs`, `rifting.rs`, `init.rs` and `collision.rs`; for `state.rs` it only says `Contact` gains the slab length, and `Plate.omega` stays (the balance becomes its source), so no row here carries the mark.

Already ledgered, no new row (same value at the same place): none of the four files' own values was found in an existing row by symbol grep. Related rows elsewhere are named as `see XXX-NNN` in the status cells.

## Flags
- CRE-014: `pool::CONSERVED` is documented as "the conserved (felsic-family) pools: never subducted, accreted instead" and equals 5, which covers pools 0 to 4 (sediment, sedimentary, metamorphic, felsic plutonic, felsic volcanic). Three of the five are not felsic. PLT-136 says the code "conserves the felsic family" and the erosion order lists mafic pools as replaced at overlap; the comment and the value do not describe the same set.
- CRE-034: the plan (section 8.5, P2-01 as built) says the column rule and the Noddy port agree to 1e-5 block on every lattice point; the engine classifies a point as a side flip at a difference above 1e-3 block when it is within 1e-6 of a fault plane, and only the remaining points enter `worst`. Whether a side flip can hide a disagreement larger than 1e-5 is not recorded; the tests assert `worst < 1e-5` on the non-flipped points.
- CRE-004 and CRE-003: the noise frequencies the callers pass (1.6 to 4.0 on the unit sphere) correspond to features of roughly 0.25 to 0.6 radian, but no document ties these sizes to Earth plate or continent sizes; the existing rows PLT-008, PLT-015 and PLT-087 record amplitudes and frequencies as `game-choice` or similar with no source.
- CRE-016: `Plate.omega` is a plate motion field; the force-balance design replaces how it is set but not the field, so these rows are not `pending-rewrite`. If the design is implemented with a different state layout, CRE-016 and CRE-030 need revisiting.
- Scope note: stage 1 build log (STATUS.md) listed `plates/dynamics.rs`, `geometry.rs`, `noise.rs`, `state.rs` and `structure/deform/lattice.rs` as not covered. This ledger covers the four named in this package; `plates/dynamics.rs` is not in it.
